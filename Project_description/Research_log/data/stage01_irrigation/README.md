# Снимок этапа 0.1: гидрология LEO West

Период: `[2025-05-01 00:00:00, 2026-10-01 00:00:00)`, исходное время Oracle.
Научный результат и ограничения: [аудит 0.1](../../details/00_irrigation_audit.md).
**Ограниченный результат 0.1-B принят и закрыт 27.10.2026** как гидрологический
вход разрешённого пилота. Полный календарь не установлен; 37 согласованных
дат увлажнения не имеют подтверждённых границ события и поданного объёма.
Этап 0 в целом и его другие ограничения сохраняются.

Единый график: [влажность, потенциал и десять масс](../../output/stage01_irrigation/pilot_hydrology_17months.png).

Непрерывность означает календарные ряды с сохранёнными разрывами.
`is_nonservice_value` = конечное значение, отличное от `−9999`; это не
метрологический допуск. Пять исходных столбцов Oracle не менялись.
VWC относится к соседней точке (2,4), 5/35 см; MPS-2 — к W_x1_y4,
20/50 см; массы — к десяти опорам всего склона. Потенциал не преобразован
в VWC, а масса — в поданную воду. EX81 в этот принятый вход не входит;
сообщение о его шуме не является независимо доказанной поломкой.

`usable` означает только конечное значение, отличное от `-9999`.
Это не признак доказанной исправности или метрологической точности.
Все первые/последние времена в итоговом паспорте относятся к указанному
периоду, не ко всей истории датчика. Диагностическая 15-минутная ячейка
не заменяет исходную временную метку. `observation_start/end` в реестре дат —
сутки сравнения, не время включения и выключения дождевания.

Воспроизведение текущего принятого входа по зафиксированному сырью без Oracle:

```bash
MPLCONFIGDIR=/tmp/co2flux-mpl python3 Project_description/sensorDB/stage01_irrigation_audit.py pilot
python3 -m unittest discover -s Project_description/sensorDB/tests -p test_stage01_hydrology_pilot.py -v
```

Команды запускаются из корня репозитория. Они не обновляют исходный снимок
и не пересчитывают прежние результаты аудита. Архивные `analyze`/`validate`
относятся к исходному аудиту 23.10 и не являются текущей командой 0.1-B.
