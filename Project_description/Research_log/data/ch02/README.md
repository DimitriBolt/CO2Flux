# Ноябрь 2017: снимок исходных записей

[Оглавление](../../README.md) · [Глава 2](../../02_monthly_changes.ipynb) · [Проверки](../../details/02_data_checks.md)

`measurements.csv` — побайтовая копия выгрузки Oracle от 25.09.2026 для
W_R4_C-4, D1/D2/D3, `sensorid` 994/1010/1026, `variableid=9`.
Всего 31 746 строк, по 10 582 на датчик. Интервал:
`2017-11-01 00:00:00 <= localdatetime < 2017-12-01 00:00:00`.
Время местное из базы, без преобразования часового пояса. Данные не усреднялись;
все повторные записи и постоянные участки сохранены.

- `reference_summary.csv` — сводка диагностик по каждому датчику.
- `reference_duplicates.csv` — все 73 группы повторных временных меток.
- `reference_constant_runs.csv` — точные постоянные участки длительностью от часа.
- `reference_gaps.csv` — интервалы между соседними записями длиннее 1,5 медианного шага.
- `reference_daily_counts.csv` — число записей и различных временных меток по суткам.
- `database_duplicate_example.csv` — отдельный SELECT шести записей на 06.11.2017
  16:20:05 с `VALUEID`; подтверждает, что повторы присутствуют в базе.
- `database_columns.csv` — названия и типы столбцов `LEO_WEST.DATAVALUES`.
- `provenance.json` — параметры, SQL, время выгрузки и контрольные суммы восьми CSV.

Пять таблиц `reference_*.csv` служат эталонами проверки. Notebook пересчитывает
диагностики из `measurements.csv`, а не берёт готовые числа вместо расчёта.
Структура таблицы базы не содержит отдельного признака качества или источника записи;
по одному `VALUEID` выбрать более достоверное значение нельзя.

Обычный запуск главы не обращается к Oracle и не меняет снимок. Скрипт
[prepare_chapter02.py](../../prepare_chapter02.py) отказывается перезаписывать его.
Обновление выгрузки требует отдельной версии и записи причины в журнале.
